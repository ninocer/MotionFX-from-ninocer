# MotionFX · Plugin Studio

Android-приложение на Kotlin/Jetpack Compose и расширяемый **Plugin API 1.0.0**.
Текущий этап — система плагинов с рабочим сквозным сценарием:
**импорт изображения → эффекты/переход/анимация → предпросмотр → PNG или H.264 MP4**.
Минимальная версия — Android 13. Интерфейс на русском и английском, работа офлайн.

## Скачать APK на Windows 11

Устанавливать Android Studio, Android SDK, JDK или Gradle на Windows не требуется.

1. Откройте вкладку **Actions** этого GitHub-репозитория.
2. Выберите workflow **Android APK**, затем запуск для нужной ветки/коммита.
   Сборка запускается при push и pull request; на ветке по умолчанию доступен также **Run workflow**.
3. Дождитесь успешного задания **Test, lint and build Debug APK**. Ошибки и stacktrace находятся в его логах.
4. Внизу страницы запуска, в **Artifacts**, скачайте **MotionFX-debug-apk**.
5. Распакуйте ZIP: внутри `app-debug.apk`. Перенесите APK на Android и откройте для установки.
   Для установки собственного Debug APK Android может запросить разрешение установки из выбранного источника.

Это Debug APK с отладочной подписью. Release-подпись и публикация в магазине не настроены.
Результаты тестов доступны в `MotionFX-check-reports` и `MotionFX-device-test-reports`.
Готовый пример плагина — артефакт `MotionFX-starter-plugin`.
Состояние конкретной сборки подтверждается результатами Actions; наличие workflow само по себе не означает, что он уже был запущен.

## Что реализовано

- Версионированный API и формат `.mfxplugin`: манифест, описание, автор, версия, API/app ranges, зависимости, SHA-256.
- Установка, удаление, включение и отключение, ограничения зависимостей, проверка совместимости и точных версий в проекте.
- Пользовательские эффекты из безопасных операций; переход crossfade; пресеты анимации прозрачности;
  GPU-графы, которые приложение переводит в GLES3, с CPU fallback.
- Одинаковый `FrameEngine` для предпросмотра и экспорта, явное время композиции, обработка альфа-канала.
- Ленивые графы; отключённые пакеты не держат шейдеры, текстуры, фоновые задачи или графы эффектов.
- Атомарные записи проекта и реестра, резервная копия, восстановление после повреждения основной записи.
  Отсутствующий или неисправный плагин не удаляет настройки из проекта.
- Изолированное применение с диагностикой, карантин повреждённых пакетов и продолжение обработки остальных эффектов.
- Реальный H.264 MP4 через MediaCodec/MediaMuxer и PNG через MediaStore; прогресс и отмена видеоэкспорта.

Пример `examples/starter.mfxplugin` встроен в APK. Он содержит **Amber Light**, **Crossfade**,
**Soft Fade In** и **Cinema Vignette GPU**. При первом запуске включается пример Amber Light;
новые внешние пакеты устанавливаются отключёнными. Удалённый пользователем пример не переустанавливается при каждом запуске.

## Границы текущего этапа

Это рабочая база для пункта «Система плагинов», а не завершённый аналог всего After Effects.
Текущий экран работает с одной трёхсекундной композицией из изображения, 640×360, 24 fps.
Crossfade использует встроенную цветовую карту как второй вход. Экспорт MP4 композитит прозрачность на чёрный фон.
Импорт видео/аудио, полноценный многодорожечный редактор, 4K/H.265, маски, графический редактор кривых
и каталог сторонних пакетов относятся к следующим этапам.
Производительность на конкретных OPPO/realme/Xiaomi не измерялась.

**Совместимость с Adobe After Effects `.aex` / `.plugin` не реализована.**
Пакеты MotionFX не могут содержать произвольный код, DEX/JAR/SO, JavaScript или исходный GLSL.
Контрольная сумма проверяет целостность, но не подлинность автора; система подписей издателей пока не реализована.

## Архитектура и API

- `plugin-api/` — платформонезависимый Kotlin API, валидатор ZIP/JSON, lifecycle, интерпретатор, GLSL-генератор, хранение.
- `app/` — Compose-интерфейс, системный выбор файлов, GLES3 backend, аппаратный путь кодирования MP4 и MediaStore.
- `examples/starter/` — исходники рабочего пакета.
- `tools/package_plugin.py` — детерминированная упаковка `.mfxplugin`.
- `.github/workflows/android.yml` — облачные JDK/SDK, JVM-тесты, Lint, Debug APK, Android-интеграционные тесты и артефакты.

Подробный контракт, модель безопасности, формулы, жизненный цикл и расширение будущим каталогом:
[docs/PLUGIN_API.md](docs/PLUGIN_API.md).

## Сборка в облачной Linux-среде

При уже установленных JDK 17 и Android SDK 35:

```sh
./gradlew --no-daemon --stacktrace :plugin-api:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest
```

В текущей среде Codex инструменты устанавливаются вне репозитория:

```sh
bash tools/bootstrap-cloud.sh
source tools/cloud-env.sh
```

Скрипт проверяет контрольные суммы JDK и SDK tools, устанавливает SDK и запускает проверки/сборку.
Использует существующий checkout; отдельный Git worktree не нужен.
Обычные переменные — `JAVA_HOME`, `ANDROID_HOME`, `ANDROID_USER_HOME`, `GRADLE_USER_HOME`.
Ключи API и секреты для сборки/работы приложения не требуются.

APK: `app/build/outputs/apk/debug/app-debug.apk`.
JVM-отчёт: `plugin-api/build/reports/tests/test/index.html`.
Lint: `app/build/reports/lint-results-debug.html`.

На подключённом Android 13+ или эмуляторе:

```sh
./gradlew :app:connectedDebugAndroidTest
```

Инструментальные тесты сравнивают настоящий GLES-рендеринг с CPU, экспортируют MP4,
проверяют кодек/размер/число кадров/временные метки и декодируют изображение.
Эмуляторные тесты запускаются отдельным заданием GitHub Actions. Запуск на физических устройствах не заменён эмулятором.

## Создание своего пакета

Скопируйте `examples/starter/`, задайте уникальный ID, отредактируйте манифест и декларативные операции.
Команды выполняются в облачной среде:

```sh
python3 tools/package_plugin.py examples/starter examples/starter.mfxplugin
python3 tools/package_plugin.py examples/starter app/src/main/assets/starter.mfxplugin
./gradlew :plugin-api:test
```

В приложении: **Плагины → Установить пакет → включить → добавить эффект в композицию**.
